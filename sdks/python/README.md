## Errors

When the API returns a non-success status code (4xx or 5xx), the SDK raises a subclass of
`ApiError` from `postman_custedu.errors`. The HTTP status code is
available via `status_code` and the (typed, when the endpoint declares one) error body via `body`.

```python
from postman_custedu.errors import ApiError, NotFoundError

try:
    client.some_resource.some_method(...)
except NotFoundError as e:
    # handle a 404 specifically
    pass
except ApiError as e:
    print(e.status_code)
    print(e.body)
```

## Advanced

### Retries

Requests that fail with a retryable status code (408, 429, and 5xx) are automatically retried with
exponential backoff, up to a configured number of attempts. Configure the limit on the client, or
per call:

```python
client = PostmanCusteduApi(retry={"attempts": 3})
client.some_resource.some_method(request_config={"retry": {"attempts": 1}})
```

### Timeouts

```py
from postman_custedu import PostmanCusteduApi

sdk = PostmanCusteduApi(timeout=10)
```

### Redirects and Logging

By default, the SDK follows HTTP redirects (3xx responses) automatically. Pass
`follow_redirects=False` to get the redirect response back as-is instead, and pass a standard
library `logging.Logger` as `logger` to log every outgoing request and its response:

```python
import logging

logger = logging.getLogger("PostmanCusteduApi")
logger.setLevel(logging.INFO)
logger.addHandler(logging.StreamHandler())

client = PostmanCusteduApi(follow_redirects=False, logger=logger)
```

Both can also be changed later, with `client.set_follow_redirects(False)` and
`client.set_logging(logger)`. `Authorization` and `Cookie` header values are always redacted in
logged output.

### Per-request Options

Every method accepts a `request_config` dict to override behavior for a single call — a different
base URL, additional headers, or a timeout:

```python
client.some_resource.some_method(
    request_config={
        "base_url": "https://staging.example.com",
        "timeout": 5,
        "additional_headers": {"X-Custom-Header": "value"},
    }
)
```

`additional_body_parameters` sends keys the SDK does not model — a beta field, say — without
waiting for a new release. They are merged into the request's JSON object body under the wire
names given, and override a field the SDK already serialized under the same name:

```python
client.some_resource.some_method(
    body,
    request_config={"additional_body_parameters": {"secret_feature_enabled": True}},
)
```
